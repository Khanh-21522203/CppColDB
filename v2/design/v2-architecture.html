CppColDBv2 — desired architecture

scaffold module map · C++20 · embedded columnar OLAP engine

CppColDBv2 is an abstractions-first, modular scaffold refactor of CppColDB, a DuckDB-inspired embedded columnar OLAP engine, modeled on the SharpDB V2 rewrite. This is scaffold only: declarations are complete across every module, but non-trivial method bodies throw CPPCOLDB_NOT_IMPLEMENTED(). The tree is designed to compile and link; it does not run a query yet. The diagram below maps the six build targets, their one-directional dependency graph, and the bottom-up order in which their contents are meant to be implemented.

What changed from v1

carried over from the SharpDB V2 rewrite
  • Abstractions layer introduced. Every core engine subsystem now has a pure-virtual I* interface under engine/abstractions/; v1 had no interface layer.
  • Strong-typed IDs. BlockId, TransactionId, RowGroupId, RowId, ColumnId, TableId, Timestamp are distinct structs, replacing v1's raw using aliases.
  • New primitives/ folder. Domain-agnostic concurrency and allocation utilities (CacheLinePadded, Spinlock, ObjectPool, ArenaAllocator, ConcurrentQueue, bit_utils) did not exist as a separate concern in v1.
  • Nested namespaces. cppcoldb::<module>::<domain> replaces v1's flat cppcoldb namespace.
  • Modular multi-target CMake. Six independent targets (cppcoldbv2_common, cppcoldbv2_engine, cppcoldbv2_infrastructure, cppcoldbv2_sql, cppcoldbv2, cppcoldbv2_cli) replace v1's single globbed library.
  • Ports / adapters split. Engine defines I/O ports (abstractions/io/); infrastructure supplies the concrete adapters (PosixFileSystem, SystemClock, loggers).
  • 1:1 mirrored test tree. The test/ tree mirrors src/ module for module, with fakes implementing the same abstractions.
